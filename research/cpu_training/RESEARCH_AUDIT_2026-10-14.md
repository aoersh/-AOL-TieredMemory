# 项目背景

**审稿判断：项目有可信的负结果和机制线索，但尚未形成经过验证的新方法，也不足以支撑“现有 CXL tiering 在 DNN training 中普遍收益有限”的论文主张。** 最需要补的是研究问题与有效对照，继续增加旧参数矩阵的边际价值很低。

科研探索从零开始，但 SOAR、ALTO、TPP/NBT/Nomad/Colloid 集成和顺序/指针追踪微基准来自上游。它们是已有工作与实验基础，不能算本项目的原创贡献。本项目新增价值主要在硬件适配、训练对象管理、实验审计以及真实 CXL 上的性能行为证据。

环境为 Xeon 6515P、真实 CXL node2、本地 DRAM node0、Linux `6.8.12-138-soaralto`、PyTorch `2.6.0+cpu`。训练使用 CPU0–7；历史显式迁移使用 CPU8。当前主体 workload 是自编两层、显式 attention、FP32 eager Transformer，固定合成输入、SGD；MLP 主要用于正确性回归。

**“CXL 慢于本地 DRAM”是基线事实，不是贡献。** CXL 的价值来自容量、成本和系统资源折中；论文不需要证明 CXL 本身比无限容量的本地 DRAM 更快。应比较相同快内存约束下的合法策略，或者证明相同吞吐率下能减少多少 DRAM。当前尚未建立可信的整进程 DRAM 容量约束或这样的性能/容量曲线。

同样，“热点不等于性能关键”和“迁移成本可能抵消访问收益”已是上游论文的明确动机。把这两句话换成 tensor 表述，不足以构成新的系统论文。

# 当前研究问题

## 当前主张与证据的缺口

| 优先级 | 审计发现 | 对论文的影响 |
| --- | --- | --- |
| 高 | 尚未证明热度排序选错：没有可靠总访问频率标签，也没有原生训练中的同预算 hotness 对照 | “热点不等于值得迁移”在本项目仍是候选假设，不能用标题替代实验 |
| 高 | 主要预取证据来自额外保存副本；同批原生校准显示其显著增耗 | 负收益可以证明当前实现不划算，不能证明已有 tiering 方法普遍无效 |
| 高 | 早期 budget 是累计迁入上限，后续 saved 配额和 C10 配额都是部分账本 | 无法宣称整进程容量收益；主线的稀缺资源前提尚未闭合 |
| 高 | 没有实际 CPU 训练中的完整 TierTrain、SOAR 或 ALTO 强对照 | 简单 FIFO/同步迁移不能代表现有方法的最佳水平 |
| 高 | 新 mmap 分配器全 DRAM 控制显著慢于默认路径 | 放置策略效果与执行器伪影难分；同执行器公平仍不等于有实际可用价值 |
| 中 | 仅自编两层 FP32 eager attention；峰值远小于机器 DRAM | 超过 LLC 不是 DRAM 容量不足，也不能代表优化后的 BERT/LLaMA 或真实 CPU 训练 |
| 中 | LRU/PTE、缓存、缺页、复制和重叠同时变化 | 目前只能形成机制解释，不能给出锁的独立墙钟贡献 |
| 中 | 独立进程数少、明显漂移、探索多重比较、历史 governor 未固定 | 大幅减速可信度高，小幅增益排序和跨配置泛化不足 |

**删除大部分活跃实验入口后，值得保留的核心问题是：在明确的 DRAM 预算下，CPU 训练应把快内存分给哪些 storage，使其端到端价值超过执行和管理成本？** 是否动态迁移是后续条件问题，不能预设为解法。

具体先问：在同一预算、同一计算和低开销执行路径下，初始放置的不同对象集合是否产生可重复的性能差异？若没有，就没有理由开发复杂排序器。若存在，再问动态迁入能否在剩余生命周期内回收其成本，并且是否比静态放置更好。

这比“把 CXL 数据搬得更快”有价值，因为它允许合法选择直接访问 CXL、初始放 DRAM、推迟或拒绝迁入。目标可以是更好的时间/DRAM 曲线，而不是必须胜过无限容量全 DRAM。

## 分析模型应如何使用

`AccessCount × (T_CXL - T_DRAM) - MigrationCost - ManagementOverhead` 只适合作为直觉。原始访问次数不等于到达 CXL 的请求次数；CPU 缓存、MLP、算子内部复用、向量化和多线程使单次延迟不能线性累加。迁移墙钟与训练同时执行，也不能直接扣掉完整迁移墙钟后再扣前台干扰。

首先定义经验标签：

\[
\Delta_i(B,s)=T_{\mathrm{Direct}}(B,s)-T_{\mathrm{Migrate}\ i}(B,s)
\]

其中预算 B、初始状态 s、训练图、对象生命周期和其他策略设置固定；每条路径都计入真实初始化、管理、重置/回收成本。这个标签回答具体动作的端到端净价值，不能跨不同实验场景拼接。

可研究的决策近似是：

\[
V_i \approx G_i^{\mathrm{remaining}}-C_i^{\mathrm{exposed}}-I_i-C_i^{\mathrm{management}}-\lambda(B)A_i
\]

\[
A_i=\int b_i^{\mathrm{DRAM}}(t)\,dt,
\qquad \sum_i b_i^{\mathrm{DRAM}}(t)+b_{\mathrm{reserved/staging}}(t)\le B.
\]

G 是迁入完成后剩余使用的可获益时间；C_exposed 是暴露在关键路径上的成本；I 是对前台的额外干扰；A 是快内存占用积分。lambda 需要明确单位与估计方法。各项必须定义互不重复的计量边界；公式不是现有数据的因果分解，也不保证对象收益可加。

占用积分用于分析机会成本，**不能替代任意时刻的峰值约束**。若用池，空闲但保留的 DRAM 页也占物理容量；若有迁移 staging，应计入可用预算。预测误差大时，保守拒绝迁入应是可选动作，但它的正确率和误拒收益必须在独立数据上检验。

上述行属于不同协议/批次，不能将绝对时间串起来画成“方法逐步变快”的曲线。60 个原始进程均值复算只核对了相应摘要的计算一致性，没有增加独立样本数。

已有工作中最有科研潜力的是“迁移成本随前台分配阶段变化，按时预取仍可能拖慢关键路径”的机制线索。原生整体放置对照是必要地基；测试、硬件移植和参数向量化是工程支撑，不能充作主要贡献。

提交 `6fdc227` 的“完整训练收敛验证”应理解为这一实验方向的收敛决定。固定合成输入与状态哈希不能证明真实数据任务达到训练精度或收敛目标。

# 已失败方向以及失败原因

| 方向 | 失败或受限情况 | 科研决定 |
| --- | --- | --- |
| 全量 FIFO 预取 | 需求顺序倒置与大额暴露等待；基线较弱 | 冻结为历史机制控制，不能再拿它证明新策略有效 |
| 仅靠需求顺序/ranked 修复 | 队列局部改善，没有稳定胜 Direct | 停止当前固定图上的队列排序扫描 |
| 当前 ID10/ID34 页面迁入 | 同步迁移显著慢；修正异步 ID10 仍明显慢；当前对象放置未发现实用整步优势 | 停止继续试延迟、页批大小或形状来找赢家 |
| 用参数向量化作为研究主贡献 | 准备变快，但调用/干扰变化抵消，整步改善不稳定 | 保留已完成修复，停止把局部构造速度包装成训练收益 |
| GIL 返回等待/长睡眠主因 | C 内/外时钟与线程 CPU 不支持其占主要成本 | 关闭这条主因假设；没有新证据不再重复排查 |
| “只要迁移按时就可隐藏成本” | 需求等待很低而整步明显变慢 | 当前场景已反证这种充分条件；必须计入前台干扰 |
| 用全负样本训练 Direct/Prefetch 分类器 | 没有稳定正收益动作，常数 Direct 已可解释当前选择 | 停止 AOL 阈值调优和复杂 ML；相关性不等于决策价值 |
| shared interval 被当 tensor AOL | 旧生命周期日志截断，pack→unpack 含义错误，计数共享 | 作废对应证据；保留调试记录，不能否定原 AOL |
| “有 DRAM 空位就迁入” | 两档需求策略迁入集合一样、每步大量同步搬运，约增耗 104 ms | 停止该准入规则搜索；它不能代表优化后的 TierTrain |
| 逐张量 mmap/munmap 分配器上的性能策略 | 改变缓存复用、缺页、锁和页管理；全 DRAM 控制增耗约 77% | 冻结为覆盖/正确性原型；停止预算、size threshold 和 shape 搜索 |
| 多模型原生 DRAM/CXL 表格作为论文主线 | 能量化各 workload 减速，但若无新规律和决策，只增加常识验证 | 不直接扩成 BERT/ResNet/Transformer/LLaMA 四模型大矩阵 |
| 强制三组件融合 | 没有训练上的评分标签、权限冲突证据或 ALTO 增量 | 从当前论文路线删除强制集成目标；不称其已被实验否定 |

失败原因有两类：研究前提没有成立，以及实现过度扰动了被研究对象。现有证据不足以将所有负结果归因到 CXL 物理层或 Linux 内核；尤其原生放置实验没有迁移，不能用迁移 worker 的 LRU 采样解释其全部减速。

# 下一阶段实验计划

**建议用 7–10 个工作日完成继续/停止判断。先过问题验证，再决定是否投入 4–6 周系统与论文工作。** 这些是未来计划，本审计没有执行。

## 第 0 道门：问题与文献，1–2 天

1. 选定论文主问题为“同快内存预算下的 CPU 训练对象分配”，动态迁移暂为条件扩展。
2. 获取并阅读 TierTrain 正文/实现，建立对照表：管理对象、初始放置、卸载、预取准入、剩余使用、成本、容量、预测/校准开销。补检相关的成本感知 tiering 与训练内存管理工作。
3. 写一页可检验的主张：哪种已有决策会在什么训练条件下选错，预期改进来自哪里，用什么同预算对照证伪。

如果候选差异已被覆盖，而且不能提出新的具体条件或机制，就停止这一方法方向。不要先写系统再找创新。

## 第 1 道门：低开销执行与容量定义，2–3 天，上限一周

先评估现成 CPU 放置接口/运行时是否可复用。优先考虑对少数独立、长寿命 storage 做首次放置：默认计算路径仍使用原分配器，选择的 storage 使用独立有界 DRAM 映射，初始化和最终清理计入。它比每步复制全部 saved tensor 更可能保持低扰动，但可行性和别名安全需要验证，不能作为已完成方案。

若采用这一收窄方案，首先只研究能通过该路径正确管理的对象类别。非受管匿名分配保持相同 CXL 放置，报告固定 DRAM 残余、文件页/COW 与实际占用；不能用普通堆页 rounding-down 迁移共享页面。只有存在必要性且前述方案不足，才评估有界池等新分配执行方式。

容量可选两种诚实定义：经验证的整进程 node0 物理预算，或者明确的受管 tensor-storage 预算加账本外驻留报告。首篇不必为了术语完整从头实现全进程额度，但论文不能把后者写成前者。使用池时，保留但空闲的快层页也计入预算，不能只算 live tensor。

验收条件：同样的放置，在受控默认路径参考与候选执行路径之间没有明显实用增耗；3% 可继续用作内部筛查门槛，需同时看区间与噪声。诊断证明数值、存储别名、生命周期、初始节点与实际额度正确；正式计时取消详细采样。分配器统计的“全部释放”不能替代物理驻留统计。

超过一周仍只能得到当前约 77% 增耗级别的实现，就停止容量策略系统开发，不把优化分配器变成无限前置任务。

## 第 2 道门：是否存在可利用的分配差异，2–3 天

首个新案例预先选一个 CPU 训练有依据、持久 storage 占比足够高的稀疏 embedding/推荐或类似 workload；选择理由是跨步复用与短寿命 attention 保存值不同，**不是预设它一定获益**。最多做一个新算子族，不同步铺开 BERT/ResNet/LLaMA。旧自编 Transformer 留作负例。

预先限定两档预算和少量对象组。预算必须低于被管理部分的实测全 DRAM 峰值，并足以制造对象之间的选择竞争；不以全工作集超过 LLC 代替这个条件。若首阶段只支持持久 storage，就只在不同持久对象组间比较，不声称已研究所有激活/临时输出。

比较组为：Direct、简单先到先得/固定放置、明确可测的访问强度参考、独立探索确定的候选放置。原生全 DRAM 只作无约束性能参考。尚无法可靠测频率时，应披露并先研究“简单规则与候选”之间的差异，不制造名义 hotness 基线。

有限配置中的最佳放置只叫经验参考，不叫严格 oracle 上界；对象收益可能不加和。选择使用探索数据，独立确认使用不同进程/时间区组，不能在同批挑最快组合后直接报告其置信区间。

探索可各三进程；有候选后至少五个随机区组的独立进程确认。沿用 3% 作为内部实用门槛，不能把它当论文录用门槛。若区间仍宽且跨门槛，只允许一次预先约定的确认；保留“不确定”，不能写成“证明无收益”。

继续条件：同预算合法对象分配有可重复整步优势，或相同吞吐率下显著少用 DRAM。若所有可行选择都接近 Direct，停止策略开发，不继续扩大形状寻找正例。

## 第 3 道门：最小方法和必要对照，通过前两门才进入

先做一个简单的 profile-guided 初始放置规则，使用实际边际收益及容量占用排序，并保留 Direct。比较策略必须共用执行机制。只要静态策略能成立，就可以围绕分配价值完成论文，不必加入动态迁移。

动态扩展只有两个进入理由：初始放置不能适应变化的活跃集合，或者已经测到迁入后的剩余使用能补偿搬运成本。此时再比较 Direct、静态放置、代表性训练预取、成本感知准入；计入所有观测、探索、迁出、重置、staging 和清理。相同初始 CXL 的 Direct 不迁移，Prefetch 迁移，这是合法动作差异；公平不是强迫 Direct 也搬相同字节。

如果进入动态阶段，优先验证已有机制线索：同样及时完成的迁移，在原生前台分配密集和较少分配的自然阶段是否产生不同的整步价值。只测预先选择的窗口；机制控制和可部署调度要分开。先验证有无实际干扰，再决定是否值得引入分配感知拒绝/推迟规则。

AOL 只有在“大小、剩余使用、访问强度和阶段”这些简单特征之后仍有独立测试上的增量时加入。预测器报告时间单位误差、错误迁入损失、误拒收益和测量开销，不只报告相关系数。

## 论文阶段与停止分支

只有主线过门，才增加第二个机制不同的 workload、预算曲线、线程数/自然阶段变化、失败案例和一个实际强基线。若论文点名 TierTrain，就必须运行官方实现或透明且经核验的重实现；没有实现时，不把当前 FIFO 改名为 TierTrain。

若前两门失败，明确停止“收益感知 tensor 分配/预取系统”这条路线。可选择一个替代问题：**真实 CPU 训练中的页面分配与迁移耦合是否使重叠成本模型失效，以及能否预测何时应绕过迁移。** 这利用已有机制线索，但仍需原生代表案例、可复现的条件边界和一个低开销准入改进。若效应主要由人工 saved 副本引入，或者仅限本机特定内核，也停止将其作为完整系统论文，保留为技术报告/负结果材料。

不能将未通过容量路线自动包装成“大范围性能分析论文”。纯分析论文也需要代表性、非平凡规律和能指导实际系统设计的结论。

# 论文贡献预测

| 潜在贡献 | 当前成熟度 | 完成条件 |
| --- | --- | --- |
| 训练对象的快内存价值及失败边界分析 | 有负例和机制线索；缺同预算、原生对象级证据与代表性 | 给出哪个对象/阶段为什么值得或不值得放快层的可检验结论，区分初始放置和迁入 |
| 能拒绝无价值动作的简单分配/准入方法 | 尚未实现和验证 | 与相关工作有具体差异，同预算优于强基线，全部开销可核算 |
| 时间/DRAM 折中及可靠 artifact | 审计与存档基础较好，性能/容量曲线缺失 | 多个有机制差异的案例、独立确认、低扰动执行、反例、可重算结果 |

最可能成文的路线是“一条具体训练内存规律 + 一个简单有效决策 + 严格同资源验证”。论文可以有负例，方法也可以主动选择不迁移；但只有一组“Direct 胜过自己的高开销迁移器”，目前达不到可靠的 CCF B 系统论文贡献强度。

“系统性分析”不等于测了很多配置。BERT、Transformer、tiny LLaMA 可能重复同一 attention 机制；应根据持久/临时、稠密/稀疏、复用/一次使用等维度选择 workload。成熟优化执行路径至少应有一个代表，不能所有证据都来自人为 unfused FP32 图。

现阶段无法诚实估计“论文已完成百分比”。平台与实验可信性积累较多，但创新、有效策略、容量曲线和强基线仍是决定性缺口。通过 7–10 个工作日的问题验证后，再决定论文范围及投稿目标。

# 风险分析

| 风险 | 严重性 | 决策和缓解 |
| --- | --- | --- |
| 主张被 SoarAlto/TierTrain 或其他成本感知工作覆盖 | 高 | 文献门在系统开发前；不宣称首次，不以应用迁移替代创新 |
| 可利用的分配差异本来很小 | 高 | 两预算、有限对象组、独立确认；无边界就停止，不用复杂模型补救 |
| 执行器改变 allocator/缓存/触页造成伪影 | 高 | 同放置默认参考校准；低开销门未过就不做性能策略 |
| 快内存范围与论文容量主张不一致 | 高 | 明确受管范围、固定残余、池保留页和 staging；需要整进程主张时必须升级核验 |
| 热度、AOL 与真正端到端收益混淆 | 高 | 区分总访问、带阈值 PEBS、共享背景 AOL、静态放置标签与迁移标签 |
| CPU dense training 的实际需求和 workload 代表性不足 | 高 | 先说明部署场景；预选有现实 CPU 训练依据的机制不同案例，避免只增加模型名字 |
| 单机器/6.8.12 内核的局部行为被推广 | 中高 | 保留环境限制；要作内核普遍性主张，后续需要另一环境验证，不立即改内核 |
| 独立样本少、频率/背景漂移影响小幅差异 | 中 | 时间区组、所有运行保留、训练/探索分离；n=3 无显著性不当作等效 |
| 局部收益被重复计入或初始化被藏起 | 中 | 清楚定义区间；不累加重叠迁移和前台时间；同时报整步和有明确定义的完整 run |
| 旧文档/代码重新激活已停路线 | 中 | 后续实施前收敛当前入口；历史快照冻结，排除清单明确；本轮不更改现有文件 |

当前可作出的投入决定是：**保留平台、原生参考和负结果；停止旧 attention 预取与高开销分配器策略搜索；给同预算低开销分配问题一次有期限的验证机会。** 动态迁移、AOL 和三组件集成都要重新通过自己的必要性门槛。
